# Enterprise Vault + External Secrets Operator + Argo CD Runbook

![vault-architecture](/img/decision2.png)

## Purpose

This runbook documents the complete enterprise-style Vault secret-management architecture implemented for the `sre-decision-intelligence-gitops` platform.

It covers the full lifecycle from installing Vault on an external VM, enabling TLS, preparing the jumpbox, connecting Kubernetes through External Secrets Operator, managing resources with Argo CD, configuring Vault Kubernetes authentication, creating policies and roles, creating `ClusterSecretStore` and `ExternalSecret` resources, validating generated Kubernetes Secrets, cleaning plaintext secrets from Git, and troubleshooting the exact issues seen during implementation.

The goal is to let another engineer reproduce the same architecture confidently without additional help.

---

## Final Architecture

```text
Developer / Platform Engineer
        |
        | Git commit
        v
GitHub Repository
        |
        | Argo CD watches Git
        v
Argo CD
        |
        | Syncs ESO, Vault references, ExternalSecrets
        v
Kubernetes Cluster
        |
        | External Secrets Operator authenticates with Kubernetes auth
        v
External HashiCorp Vault VM
        |
        | Stores real secret values
        v
Kubernetes Secrets generated by ESO
        |
        v
Application workloads consume Secrets
```

### Core Principle

Git contains **secret references**, not secret values.

Git is allowed to contain:

```text
ExternalSecret resources
ClusterSecretStore resources
ServiceAccounts
RBAC
Public CA certificate ConfigMap
Argo CD Applications
AppProjects
Kustomization files
```

Git must not contain:

```text
Database passwords
DATABASE_URL values with passwords
Vault root token
Vault unseal keys
Vault private keys
CA private keys
ServiceAccount JWT token values
Plain Kubernetes Secret manifests with real data/stringData
```

# 1. Secret Inventory and Design

## 1.1 PostgreSQL Secret

Generated Kubernetes Secret:

```text
sre-decision-postgres-secret
```

Keys:

```text
POSTGRES_DB
POSTGRES_USER
POSTGRES_PASSWORD
```

Vault logical path:

```text
secret/sre-decision-intelligence/postgres
```

KV v2 API path internally:

```text
secret/data/sre-decision-intelligence/postgres
```

In `ExternalSecret.remoteRef.key`, use:

```text
sre-decision-intelligence/postgres
```

Do **not** use:

```text
secret/data/sre-decision-intelligence/postgres
```

because the `ClusterSecretStore` already defines:

```yaml
path: secret
version: v2
```

Generated Kubernetes Secret:


Key:

```text
DATABASE_URL
```

Vault logical path:

```text
secret/sre-decision-intelligence/api
```

ExternalSecret key:

```text
sre-decision-intelligence/api
```

# 2. Install Vault on the External Vault VM

Run these steps on the Vault VM.

## 2.1 Install Vault

```bash
sudo apt-get update
sudo apt-get install -y gpg wget curl jq

wget -O- https://apt.releases.hashicorp.com/gpg \
  | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg

echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] \
https://apt.releases.hashicorp.com $(lsb_release -cs) main" \
  | sudo tee /etc/apt/sources.list.d/hashicorp.list

sudo apt-get update
sudo apt-get install -y vault
```

Validate:

```bash
vault version
```

## 2.2 Create Vault Directories

```bash
sudo mkdir -p /opt/vault/data
sudo mkdir -p /etc/vault.d/tls
sudo chown -R vault:vault /opt/vault
sudo chown -R vault:vault /etc/vault.d
sudo chmod 750 /opt/vault/data
```

## 2.3 Initial HTTP Vault Config

Initial HTTP is only for first connectivity validation, not the final state.

`/etc/vault.d/vault.hcl`:

```hcl
ui = true

storage "file" {
  path = "/opt/vault/data"
}

listener "tcp" {
  address     = "0.0.0.0:8200"
  tls_disable = true
}

api_addr = "http://192.168.0.61:8200"
```

```bash
sudo chown vault:vault /etc/vault.d/vault.hcl
sudo chmod 640 /etc/vault.d/vault.hcl
sudo systemctl enable vault
sudo systemctl restart vault
sudo systemctl status vault --no-pager
```

## 2.4 Initialize Vault

```bash
export VAULT_ADDR="http://192.168.0.61:8200"
vault operator init
```

Securely store:

```text
Unseal keys
Initial root token
```

Never commit these values.

## 2.5 Unseal Vault

```bash
vault operator unseal
vault operator unseal
vault operator unseal
```

Validate:

```bash
vault status
```

Expected:

```text
Initialized    true
Sealed         false
```

## 2.6 Login

```bash
vault login
```

Use the initial root token only for bootstrap.

## 2.7 Enable KV v2

```bash
vault secrets enable -path=secret kv-v2
```

If it already exists:

```bash
vault secrets list
```

Expected:

```text
secret/    kv
```

# 4. Enable HTTPS/TLS for Vault

## 4.1 Why TLS Is Required

ESO calls Vault from Kubernetes. Vault must not expose secret traffic over plain HTTP.

TLS provides:

```text
Encryption in transit
Vault server identity verification
Protection from accidental plaintext secret movement
```

## 4.2 Create an Internal CA

```bash
mkdir -p ~/vault-tls
cd ~/vault-tls
openssl genrsa -out vault-ca.key 4096
openssl req -x509 -new -nodes \
  -key vault-ca.key \
  -sha256 \
  -days 3650 \
  -out vault-ca.crt \
  -subj "/CN=platform-vault-ca"
```

Important:

```text
vault-ca.crt = public CA certificate, safe to distribute
vault-ca.key = private CA key, never commit
```

## 4.3 Create Vault Server Certificate

Create OpenSSL config:

```bash
cat > vault-server-openssl.cnf <<'EOF'
[req]
default_bits       = 4096
prompt             = no
default_md         = sha256
distinguished_name = dn
req_extensions     = req_ext

[dn]
CN = vault.platform.local

[req_ext]
subjectAltName = @alt_names

[alt_names]
DNS.1 = vault.platform.local
IP.1  = 192.168.0.61
EOF
```

Create key and CSR:

```bash
openssl genrsa -out vault.key 4096
openssl req -new \
  -key vault.key \
  -out vault.csr \
  -config vault-server-openssl.cnf
```

Sign certificate:

```bash
openssl x509 -req \
  -in vault.csr \
  -CA vault-ca.crt \
  -CAkey vault-ca.key \
  -CAcreateserial \
  -out vault.crt \
  -days 825 \
  -sha256 \
  -extensions req_ext \
  -extfile vault-server-openssl.cnf
```

Verify SAN:

```bash
openssl x509 -in vault.crt -noout -text | grep -A2 "Subject Alternative Name"
```

Expected:

```text
DNS:vault.platform.local, IP Address:192.168.0.61
```

This is critical because the `ClusterSecretStore` initially uses:

```text
https://192.168.0.61:8200
```

If the certificate does not include the IP SAN, ESO TLS verification fails.

## 4.4 Install TLS Files

```bash
sudo cp vault.crt /etc/vault.d/tls/vault.crt
sudo cp vault.key /etc/vault.d/tls/vault.key
sudo cp vault-ca.crt /etc/vault.d/tls/vault-ca.crt

sudo chown vault:vault /etc/vault.d/tls/vault.crt
sudo chown vault:vault /etc/vault.d/tls/vault.key
sudo chown vault:vault /etc/vault.d/tls/vault-ca.crt

sudo chmod 644 /etc/vault.d/tls/vault.crt
sudo chmod 600 /etc/vault.d/tls/vault.key
sudo chmod 644 /etc/vault.d/tls/vault-ca.crt
```

## 4.5 Update Vault Config for TLS

`/etc/vault.d/vault.hcl`:

```hcl
ui = true

storage "file" {
  path = "/opt/vault/data"
}

listener "tcp" {
  address       = "0.0.0.0:8200"
  tls_cert_file = "/etc/vault.d/tls/vault.crt"
  tls_key_file  = "/etc/vault.d/tls/vault.key"
}

api_addr     = "https://vault.platform.local:8200"
cluster_addr = "https://vault.platform.local:8201"
```

Restart:

```bash
sudo systemctl restart vault
sudo systemctl status vault --no-pager
```

Vault may be sealed after restart. Unseal if needed:

```bash
export VAULT_ADDR="https://vault.platform.local:8200"
export VAULT_CACERT="/etc/vault.d/tls/vault-ca.crt"
vault operator unseal
vault operator unseal
vault operator unseal
vault status
```

# 5. Configure Jumpbox Vault CLI

## 5.1 Use a Safe TLS Path

Do not store Vault TLS files under `~/.vault/tls`. Vault CLI may expect `~/.vault` as a file/helper path.

Use:

```bash
mkdir -p ~/.vault-tls
cp vault-ca.crt ~/.vault-tls/vault-ca.crt
export VAULT_ADDR="https://vault.platform.local:8200"
export VAULT_CACERT="$HOME/.vault-tls/vault-ca.crt"
```

Persist:

```bash
cat >> ~/.bashrc <<'EOF'
export VAULT_ADDR="https://vault.platform.local:8200"
export VAULT_CACERT="$HOME/.vault-tls/vault-ca.crt"
EOF
source ~/.bashrc
```

Validate:

```bash
echo $VAULT_ADDR
echo $VAULT_CACERT
vault status
```

## 5.2 Common Jumpbox Error

Error:

```text
failed to get token helper: read /home/jumpbox/.vault: is a directory
```

Fix:

```bash
mkdir -p ~/.vault-tls
cp ~/.vault/tls/vault-ca.crt ~/.vault-tls/vault-ca.crt
rm -rf ~/.vault
export VAULT_ADDR="https://vault.platform.local:8200"
export VAULT_CACERT="$HOME/.vault-tls/vault-ca.crt"
```

# 10. Vault Policy and ESO Role

## 10.1 Policy

```bash
cat > sre-decision-intelligence-read.hcl <<'EOF'
path "secret/data/sre-decision-intelligence/*" {
  capabilities = ["read"]
}

path "secret/metadata/sre-decision-intelligence/*" {
  capabilities = ["read", "list"]
}
EOF

vault policy write sre-decision-intelligence-read sre-decision-intelligence-read.hcl
vault policy read sre-decision-intelligence-read
```

Policy meaning:

```text
ESO can read only secret/data/sre-decision-intelligence/*.
ESO cannot write, delete, or manage unrelated Vault paths.
```

## 10.2 ESO Role

```bash
vault write auth/kubernetes/role/sre-decision-intelligence-eso \
  bound_service_account_names=external-secrets \
  bound_service_account_namespaces=external-secrets \
  policies=sre-decision-intelligence-read \
  ttl=1h
```

Important fields:

| Field | Why it matters |
|---|---|
| `bound_service_account_names=external-secrets` | Only ESO ServiceAccount can authenticate |
| `bound_service_account_namespaces=external-secrets` | Only ESO in this namespace can authenticate |
| `policies=sre-decision-intelligence-read` | Assigns least-privilege read policy |
| `ttl=1h` | Limits token lifetime |

Validate:

```bash
vault read auth/kubernetes/role/sre-decision-intelligence-eso
```

Expected:

```text
bound_service_account_names        [external-secrets]
bound_service_account_namespaces   [external-secrets]
token_policies                     [sre-decision-intelligence-read]
ttl                                1h
```

## 10.3 Audience Warning

Vault may warn:

```text
Role sre-decision-intelligence-eso does not have an audience configured.
```

This is acceptable for this ESO CRD version because `kubectl explain clustersecretstore.spec.provider.vault.auth.kubernetes` showed no `audiences` field.

If `audience=vault` is set, ESO may fail with:

```text
invalid audience (aud) claim: audience claim does not match any expected audience
```

Fix:

```bash
vault delete auth/kubernetes/role/sre-decision-intelligence-eso
vault write auth/kubernetes/role/sre-decision-intelligence-eso \
  bound_service_account_names=external-secrets \
  bound_service_account_namespaces=external-secrets \
  policies=sre-decision-intelligence-read \
  ttl=1h
```

## 10.4 Test ESO Login

```bash
ESO_JWT=$(kubectl create token external-secrets \
  -n external-secrets \
  --duration=10m)

vault write auth/kubernetes/login \
  role=sre-decision-intelligence-eso \
  jwt="$ESO_JWT"
```

Expected:

```text
token_policies    ["default" "sre-decision-intelligence-read"]
```

Security cleanup:

```bash
vault token revoke -accessor <token_accessor>
unset ESO_JWT
```

```yaml
  name: vault-backend

    app.kubernetes.io/name: vault-backend
    app.kubernetes.io/part-of: platform-security
    app.kubernetes.io/component: external-vault
spec:
  provider:
    vault:
      server: "https://192.168.0.61:8200"
      path: "secret"
      version: "v2"
      caProvider:
        type: ConfigMap
        name: vault-ca-cert
        key: vault-ca.crt
        namespace: external-secrets
      auth:
        kubernetes:
          mountPath: "kubernetes"
          role: "sre-decision-intelligence-eso"
          serviceAccountRef:
            name: external-secrets
            namespace: external-secrets
```

Important fields:

| Field | Purpose |
|---|---|
| `metadata.name: vault-backend` | Referenced by ExternalSecret resources |
| `server` | Vault HTTPS endpoint |
| `path: secret` | KV engine mount path |
| `version: v2` | Vault KV v2 mode |
| `caProvider` | CA used to verify Vault TLS |
| `mountPath: kubernetes` | Vault auth mount path |
| `role` | Vault role assigned to ESO |
| `serviceAccountRef` | Kubernetes identity ESO uses to login |

Why IP was used:

```text
ESO controller pods did not have hostAliases for vault.platform.local.
The IP works because the Vault cert includes IP SAN 192.168.0.61.
```

# 17. Troubleshooting

## 17.1 Vault Sealed

Symptom:

```json
"sealed": true
```

Fix:

```bash
vault operator unseal
vault operator unseal
vault operator unseal
vault status
```

## 17.2 `.vault` Directory Error

Error:

```text
failed to get token helper: read /home/jumpbox/.vault: is a directory
```

Fix:

```bash
mkdir -p ~/.vault-tls
cp ~/.vault/tls/vault-ca.crt ~/.vault-tls/vault-ca.crt
rm -rf ~/.vault
export VAULT_ADDR="https://vault.platform.local:8200"
export VAULT_CACERT="$HOME/.vault-tls/vault-ca.crt"
```

## 17.3 Invalid Audience Error

Error:

```text
invalid audience (aud) claim: audience claim does not match any expected audience
```

Cause:

```text
Vault role expected an audience, but ESO CRD did not support setting one.
```

Fix:

```bash
vault delete auth/kubernetes/role/sre-decision-intelligence-eso
vault write auth/kubernetes/role/sre-decision-intelligence-eso \
  bound_service_account_names=external-secrets \
  bound_service_account_namespaces=external-secrets \
  policies=sre-decision-intelligence-read \
  ttl=1h
kubectl rollout restart deployment external-secrets -n external-secrets
```

## 17.4 Old Warning Events Still Appear

`kubectl describe` may show old warnings. Trust current status condition:

```bash
kubectl get clustersecretstore vault-backend \
  -o jsonpath='{range .status.conditions[*]}{.type}{"="}{.status}{" Reason="}{.reason}{" Message="}{.message}{"\n"}{end}'
```

Expected:

```text
Ready=True Reason=Valid Message=store validated
```

## 17.5 TLS Verification Failure

Symptoms:

```text
x509: certificate signed by unknown authority
x509: cannot validate certificate for 192.168.0.61 because it does not contain any IP SANs
```

Fix:

```text
Ensure vault-ca-cert ConfigMap has the correct CA.
Ensure Vault server certificate includes IP SAN 192.168.0.61.
Use DNS only after cluster-wide DNS resolves vault.platform.local.
```

## 17.6 Vault Kubernetes Backend Missing

Error:

```text
could not load backend configuration
```

Fix:

```bash
vault write auth/kubernetes/config \
  token_reviewer_jwt="$TOKEN_REVIEWER_JWT" \
  kubernetes_host="$KUBE_HOST" \
  kubernetes_ca_cert="$KUBE_CA_CERT" \
  disable_iss_validation=true
```

## 17.7 ExternalSecret Not Syncing

Check:

```bash
kubectl describe externalsecret <name> -n <namespace>
```

Common causes:

```text
Wrong remoteRef.key
Wrong remoteRef.property
Vault policy does not allow path
ClusterSecretStore not Ready
Vault sealed
Vault path missing
KV v2 key path incorrectly includes secret/data
```
